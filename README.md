# recproj2 — рекомендации товаров по истории сессии (OTTO)

Проект на данных [OTTO — Multi-Objective Recommender System](https://www.kaggle.com/competitions/otto-recommender-system). По известной истории сессии система формирует по 20 рекомендаций для каждого действия: просмотра (`clicks`), добавления в корзину (`carts`) и заказа (`orders`).

Решение состоит из двух этапов: генерация кандидатов из истории, Item2Vec и популярных товаров, затем их ранжирование с помощью CatBoost. Ноутбуки охватывают исследование данных, обучение моделей, сравнение качества этапов и формирование финального сабмишна.

## Как работает решение

1. **Item2Vec.** Для каждого типа действия обучается отдельная Item2Vec-модель на последовательностях товаров внутри сессий.
2. **Кандидаты.** Объединяются товары из известной истории и соседи вектора последних событий, найденные через FAISS по эмбеддингам Item2Vec. На один тип действия возвращается 150 кандидатов (количество можно возвращаем кандидатов можно менять).
3. **Признаки.** Для пары сессия - товар рассчитываются 52 признака с учётом целевого действия.
4. **Ранжирование.** Одна общая модель `CatBoostClassifier` (`Logloss`) оценивает кандидатов; товары сортируются по предсказанной вероятности, после чего выбирается top-20 отдельно для каждого действия.
5. **Инференс на тесте.** Для экономии ОЗУ при обработке `test.jsonl` класс `Item2VecCatboostRecommender` держит в памяти CatBoost и только одну активную модель Item2Vec с индексом FAISS, выполняя предсказания батчами в три прохода (`clicks`, `carts`, `orders`) с потоковой сборкой итогового CSV.

### Item2Vec и поиск кандидатов

| Тип действия | Размер вектора | Окно | `min_count` | Эпохи |
| --- | ---: | ---: | ---: | ---: |
| `clicks` | 64 | 10 | 5 | 2 |
| `carts` | 64 | 8 | 3 | 4 |
| `orders` | 64 | 6 | 2 | 4 |

Общие параметры: Skip-gram (`sg=1`), `negative=5`, `sample=1e-5`, `seed=11`, `workers=1`.

Для поиска используется FAISS HNSW: `M=16`, `efConstruction=200`, `efSearch=128`. Векторы нормализуются, поиск выполняется по скалярному произведению. Вектор запроса строится по последним 10 событиям с весами действий `1 / 3 / 6` и учётом времени.

### Признаки CatBoost

| Группа | Примеры |
| --- | --- |
| Взаимодействия с товаром | Число просмотров, добавлений и заказов; последнее действие; повторения. |
| Время | Давность взаимодействия, длительность истории, пауза между событиями, активность за час и сутки. |
| Состояние сессии | Длина, число уникальных товаров, доли действий, наличие истории. |
| Источники кандидатов | Оценки истории и Item2Vec, флаги источников, исходная позиция кандидата. |
| Популярность и близость | Место в популярном списке, сходство со всей историей и последним товаром. |

Категориальные признаки: `event_type`, `item_last_action`, `history_last_action`.

## Данные и временное разделение

Используется `train.jsonl`: одна строка содержит `session` и список `events`; событие содержит `aid`, `ts` в миллисекундах и `type`. Последние семь суток выделены под внешнюю валидацию:

| Параметр | Значение |
| --- | --- |
| Конец данных | `2022-08-28 21:59:59.984 UTC` |
| Граница валидации | `2022-08-21 21:59:59.984 UTC` |
| Обучающие события | `ts < VALIDATION_START_TS` |
| Будущие события валидации | `ts >= VALIDATION_START_TS` |

EDA, Item2Vec и популярность товаров используют события до границы.

## Отбор сессий и обучение CatBoost

Подходят сессии с минимум двумя событиями до внешней временной границы. Первые `max(1, floor(0.8 × n))` событий образуют историю, остальные — будущие цели (`clicks` — первый будущий просмотр; `carts` и `orders` — все уникальные товары соответствующего действия).

Отбор сохраняет реальные доли групп конверсии (`orders`, `carts_without_orders`, `clicks_only`), а внутри каждой группы — доли сочетаний длины истории (`1–5`, `6–20`, `21+` событий) и дня её последнего события в UTC.

В исходном файле train.jsonl около 12 млн сессий — обучать CatBoost на всех сразу слишком долго и не хватит оперативной памяти Kaggle. Поэтому нужно отобрать 1 200 000 сессий так, чтобы эта уменьшенная выборка была точной мини-копией всего датасета и не искажала данные.  

Почему нельзя взять просто случайные 1,2 млн сессий или первые 1,2 млн строк?

Если взять первые строки файла, в выборку попадут только первые дни месяца, а свежие дни перед валидацией потеряются.Заказов (orders) в данных намного меньше, чем простых кликов. При слепом отборе редкие комбинации (например, короткие сессии с покупкой в конкретный день) могут попасть в выборку в искажённой пропорции.

Как работает этот отбор по шагам (в два прохода по файлу):
1. Разделение каждой сессии на историю и будущее:
Берутся все сессии до границы валидации, где есть хотя бы 2 события. Первые 80% событий сессии становятся известной историей (по ней считаются признаки), а оставшиеся 20% — будущими целями (таргетами, которые модель должна угадать).   
2. Раскладывание сессий по корзинам (первый проход по файлу):
Скрипт читает файл и смотрит на 3 характеристики каждой сессии:   
Что случилось в будущих 20% (тип конверсии): был хотя бы один заказ (orders), была корзина без заказа (carts_without_orders) или были только клики (clicks_only).   Какой длины известная история: короткая (1–5 событий), средняя (6–20) или длинная (21+).   
В какой календарный день произошло последнее событие истории.   
В итоге получается набор мелких "ячеек" (например: "сессии с заказом в будущем + длина истории 6–20 + дата 15 августа"). Скрипт считает, какую долю от всего датасета занимает каждая такая ячейка.   
3. Пропорциональный отбор 1,2 млн сессий (второй проход по файлу):
Если во всём датасете на конкретную ячейку приходится ровно 1% всех сессий, то и в наш пул из 1 200 000 сессий из этой ячейки случайно отбирается ровно 1%. В результате распределение конверсий, длин сессий и дат в выборке 1,2 млн остаётся точно таким же, как во всём исходном датасете.   

| Выборка | Размер |
| --- | ---: |
| Общий пул для CatBoost | До 1 200 000 сессий |
| Непосредственное обучение | 1 080 000 сессий |
| Ранняя остановка | 120 000 сессий (10% пула) |
| Диагностика на train | До 500 000 сессий |
| Внешняя валидация | До 1 000 000 подходящих сессий |

Для каждой пары сессия — тип действия сохраняются все позитивы среди кандидатов и случайная выборка негативов до `max(3 × число позитивов, 10)` в пределах до 100 строк.

Параметры CatBoost: до 1 000 итераций, `depth=6`, `learning_rate=0.05`, `loss_function='Logloss'`, `eval_metric='AUC'`, `random_seed=11`, `early_stopping_rounds=50`, веса целевых действий `clicks=1`, `carts=3`, `orders=6`. Признаки записываются порциями в Parquet и перед обучением загружаются в `CatBoost Pool`. (Иначе не хватит оперативной памяти)
